# 通知与运维

## 通知语义

信息与订阅任务同事务提交。调用方通过批量接口一次提交 1–10 条信息，后台按该批次的 `heat_score` 降序只为新写入的最高 3 条信息创建通知任务；重复记录不会再次创建任务。订阅全部包含将来创建的热点，修改范围不会补发旧信息。停用热点不删除已有通知，停用订阅方取消排队任务，已经开始的 HTTP 请求无法撤回。

状态：`pending → sending → sent`；临时失败进入 `retry`，永久失败或达到上限进入 `failed`；禁用订阅方的排队任务为 `cancelled`。测试通知使用相同任务表和 worker。

- 同一数据库仅一个 dispatcher 持有 MariaDB advisory lock，每次发送仅占一个 HTTP 请求；同机器人发送间隔至少 3.1 秒。此模型面向低资源单机，小规模吞吐。
- 每次发送先持久化尝试记录和 60 秒租约，HTTP 超时 10 秒。进程意外退出后，过期尝试标记接收状态未知，按原尝试次数退避恢复，不无限重发。
- 每轮最多发送 5 次，间隔 1、5、15、60 分钟。手动重试开启新一轮，保留原尝试记录；只允许有效订阅方的失败任务重试。
- 超时后的重试可能重复送达。企业微信 webhook 不提供本系统可用的幂等保证，无法承诺端到端恰好一次。
- 热点消息使用企业微信 `news` 图文卡片，包含标题、热点、日期、AI 热度、总结和原文链接；标题最多 128、描述最多 512 个 UTF-8 字节，超出部分截断，卡片点击原文 URL 后由微信客户端打开。测试通知使用 `text` 纯文本。后台保留完整正文。
- 企业微信 webhook 仍投递到绑定的企业微信群；消息格式只改善卡片和链接的移动端打开体验，不能把群机器人消息变成个人微信私聊。若业务需要个人微信收件，必须另行接入公众号、客服消息或小程序等渠道。
- 只向固定 `qyapi.weixin.qq.com` 地址发送，不跟随重定向。key 加密保存，错误记录仅保留本地说明或错误码，不保存微信响应正文、webhook URL 或 key。

官方依据（2026-09-13 复核）：[消息推送配置说明](https://developer.work.weixin.qq.com/document/path/91770)列出机器人 `news`、`text` 等消息类型及字段限制；本系统对图文卡片采用标题 128、描述 512 个 UTF-8 字节的保守上限，并按每机器人至少 3.1 秒间隔发送。[全局错误码](https://developer.work.weixin.qq.com/document/path/90313)确认 93000 为 webhook 无效或已移出群、93001 为群不允许推送、93004 为推送被停用，此类配置问题直接失败；无效内容也直接失败，45009 限流及未知错误有限重试。错误码表维护在 `server/worker.ts`。


## 检查与故障处理

- `GET <base>/health` 检查进程和数据库。队列积压、失败数与最后发送状态在后台查看，健康接口不承诺企业微信可达。
- systemd 日志使用 journald；应用不记录请求 body 或凭据。数据库暂不可用时 worker 保留任务，恢复后继续；应用启动要求迁移已完成。
- 机器人 key 无效：在订阅方编辑正确 key，发送测试通知，确认后手动重试失败记录。
- 加密 key 错误：恢复原 `ENCRYPTION_KEY`，或逐一重新录入机器人 key。不要直接更换密钥，否则历史密文无法读取。
- 定期查看失败任务、队列积压、MariaDB 数据/索引体积、磁盘、RSS、swap 和日志占用。没有自动删除信息或任务记录；历史量增长后由管理员制定保留策略。
- 搜索使用有界分页和 SQL LIKE，支持中文子串，适合首版规模；数据量很大时需评估全文索引或专用搜索，不默认引入其他服务。
- 未配置定时备份。实际部署前决定是否备份、保存位置和恢复方式；不要把备份混入 releases。数据库结构迁移应向后兼容，代码回滚不会回滚数据库。

## 本机测试注意

集成测试必须使用单独的 `*_test` 数据库；它会清空表。`.env` 不可指向生产再运行测试。测试完全模拟企业微信。浏览器测试若手动点击“测试通知”，真实运行环境会实际发消息，应使用专用测试群。
